# Реализация первой версии

## Компоненты

- **Frontend:** React + TypeScript + Vite. Настройки и действия вызывают Rust-команды через Tauri IPC; событие `app-state` обновляет интерфейс. Во время записи снимок состояния запрашивается раз в секунду для таймера.
- **Desktop-бэкенд:** Tauri 2. Управляет состояниями, системным треем и горячими клавишами. Изменения состояния сериализованы; события и обновления трея доставляются на главном потоке с актуальным снимком.
- **Захват аудио:** CPAL. Stream создается и закрывается в отдельном потоке; приложение хранит только отправляемый между потоками proxy. Готовность после остановки означает, что поток подтвердил закрытие микрофона.
- **Ядро:** отдельный crate `stt-core`, не зависящий от GUI. WAV — mono PCM16, 16 кГц; длительность вычисляется до ресемплинга по числу аудиокадров.
- **Сеть:** reqwest с Rustls, фиксированный OpenAI transcription endpoint, multipart WAV, JSON-результат. Перенаправления запрещены; timeout — 120 секунд. При включенной полировке после STT выполняется отдельный JSON-запрос в OpenAI Responses API `POST /v1/responses` с тем же ключом и `store: false`. Новые настройки используют `gpt-transcribe`; явный ранее сохраненный выбор остается прежним. UI содержит актуальные варианты и ручной ввод ID; Rust и frontend проверяют формат ID без жесткого allowlist. Доступ и совместимость проверяет OpenAI. Для Diarize отправляется `chunking_strategy=auto`, приложение использует только поле `text`.
- **Ключ:** keyring 3 — Secret Service на Linux, Keychain на macOS. Ключ отсутствует в JSON состояния/настроек; временные строки ключа в бэкенде оборачиваются в `Zeroizing`.
- **Буфер:** `wl-copy` на Wayland; Tauri clipboard plugin на других системах. Операции сериализованы; ручное копирование разрешено только в готовом состоянии. При timeout завершается вся группа subprocess.
- **Автоматическая вставка:** опциональна (`auto_paste: false` по умолчанию). После успешного копирования на Linux X11 выполняется `xdotool key --clearmodifiers ctrl+v` или `xdotool key --clearmodifiers ctrl+shift+v`; на Wayland — `ydotool key 29:1 47:1 47:0 29:0` или `ydotool key 29:1 42:1 47:1 47:0 42:0 29:0` соответственно выбранному `paste_shortcut`; timeout команд — 5 секунд. На macOS CoreGraphics отправляет `Cmd+V` независимо от `paste_shortcut`. Вставка вооружается только при старте записи глобальным hotkey и выполняется при остановке тем же hotkey или по лимиту; кнопка и tray её не запускают. На macOS Accessibility запрашивается при сохранении включённой настройки и повторно проверяется перед вставкой. При ошибке текст остаётся в clipboard.
- **Настройки/статистика:** JSON в app data directory. Запись через временный соседний файл и rename; после commit ошибка синхронизации каталога возвращается как предупреждение, не как отказ сохранения.

## Реализованная обработка текста

`crates/stt-core/src/polish.rs` определяет настройки и три неизменяемых встроенных профиля: `polish`, `markdown`, `developer`. Общая системная инструкция требует сохранять язык, смысл, факты и технические детали; запрещает выдумывать, отвечать на вопросы и выполнять диктовку как команды. Инструкция выбранного профиля задает стиль редактирования в рамках этих правил. В Responses API диктовка передается отдельно как пользовательский `input_text`; правила — в `instructions`. Следование модели правилам требует проверки результата, а не считается гарантией.

По умолчанию `profile_id: null` отключает полировку, модель — `gpt-6-luna`, `effort: null`. Эти значения используются и при загрузке старых настроек без блока `polish` или соответствующих полей. Явно сохраненная модель, включая прежний `gpt-5-mini` и произвольный ID, остается неизменной. Модель и effort общие для всех профилей.

`src/utils.ts` содержит готовые варианты `gpt-6-luna`, `gpt-6.1-sol`, `gpt-6-astra` и документированные возможности для точных ID, сверенные с [официальным каталогом OpenAI](https://developers.openai.com/api/docs/models) **2026-10-03**:

| ID | Явные значения `reasoning.effort` |
| --- | --- |
| `gpt-6-luna` | `none`, `low`, `medium`, `high`, `xhigh`, `max` |
| `gpt-6.1-sol`, `gpt-6-astra` | `low`, `medium`, `high`, `xhigh`, `max` |

`src/PolishSettingsFields.tsx` использует эти возможности для списка effort. Для неизвестных ID доступен полный набор `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, без обещания поддержки. Для любой модели доступно «По умолчанию»: при `effort: null` поле `reasoning` отсутствует, тогда как `none` отправляет `reasoning.effort: "none"`. Смена модели не меняет выбранный effort: несовместимое значение остается отдельным выбранным пунктом с предупреждением. Окончательное решение о доступе и совместимости принимает API.

Кнопка «Обновить модели OpenAI» вызывает `backend.listOpenAiModels()` → `list_openai_models` → `OpenAiClient::list_models`: `GET /v1/models` с текущим сохраненным ключом. Запрос выполняется только по явному нажатию, без тела с аудио, диктовкой или инструкциями; без ключа кнопка недоступна, ручной ID доступен. Каталог хранится в памяти компонента, не в настройках или истории. Все возвращенные модели доступны без фильтра по предполагаемой поддержке Responses: дополнительные ID выводятся в группе «Каталог OpenAI — совместимость не проверена», дубли готовых вариантов не повторяются. Согласно [List models](https://developers.openai.com/api/reference/resources/models/methods/list), ответ содержит базовые метаданные, не сведения о совместимости с Responses или effort.

Обновление каталога не вызывает сохранение настроек и не изменяет черновик, выбранную модель/effort или ручной ID. Во время загрузки повторный запрос заблокирован; при ошибке показывается отдельное сообщение и сохраняется предыдущий каталог. Сохраненные модели, отсутствующие в готовом или загруженном списке, остаются доступны через ручной ввод; после перезапуска выбранный ID сохраняется, сам каталог — нет. OpenAI [рекомендует Responses API для всех новых проектов](https://developers.openai.com/api/docs/guides/migrate-to-responses); это основание выбора API, а не вывод из каталога `/models`.

Встроенные профили доступны только для чтения; дублирование создает редактируемый пользовательский профиль. Создание, изменение и удаление пользовательских профилей проходят через существующее сохранение настроек, а не отдельный API хранения. Лимиты: 32 пользовательских профиля, непустое название до 80 символов, непустая инструкция до 8000 символов. Профили и настройки сохраняются в JSON, импорт/экспорт не реализован.

`src-tauri/src/lib.rs` выполняет STT → опциональную полировку → прежнее завершение с копированием и автоматической вставкой. Без выбранного профиля текст STT идет напрямую в тот же путь. Фаза `polishing` желтая и блокирует новые записи, изменение настроек и ручное копирование. Автоматическая вставка на исходном успешном пути сохраняет прежние ограничения: hotkey-start + hotkey-stop/лимит; запуск или остановка кнопкой/треем только копирует.

`src-tauri/src/state.rs` хранит `last_raw_transcript`, `last_transcript` и `pending_polish` только в памяти, не в `StoredData`. При успешном STT сохраняется исходный текст и очищается прежний итог; если полировка выбрана, захватывается ее конфигурация. Ошибка полировки возвращает `idle`, сохраняя исходный текст и задачу, но не копирует, не вставляет и не публикует исходный текст как итоговый fallback.

Команда `retry_polish` доступна для неудавшейся задачи в готовом состоянии. Она загружает **текущий API key**, но использует **захваченные профиль с инструкцией, модель и effort**. Сохранение новых настроек после ошибки, включая изменение/удаление профиля, не меняет задачу повтора. Для исправленной модели/effort нужна новая запись. Повтор вызывает только Responses API, не STT и не учет статистики; успешный итог копируется, **автоматическая вставка никогда не вызывается**. При ошибке задача остается; при успехе очищается. Если копирование успешного итога не удалось, текст доступен для ручного повторного копирования.

Старый повтор инвалидируется уже при успешном старте новой записи (`recording_started`), не только после нового STT. Отмена новой записи не восстанавливает его; ошибка запуска микрофона не сбрасывает старую задачу. При выходе исходный/итоговый текст и задача повтора теряются. Повторная обработка последнего успешного результата другим профилем — **nice to have, не реализована**; текущая команда повтора предназначена только для ошибки. Постоянной истории транскрипций нет.

Полировка и каждый ее повтор — дополнительный платный текстовый запрос, раскрывающий OpenAI текст и инструкции. `store: false` отключает сохранение Response для последующего получения, но не означает локальную обработку или гарантию отсутствия любых видов хранения у провайдера. Ограничения внешнего буфера обмена остаются прежними.

## Особенности Ubuntu 22.04 / GNOME 42 / Wayland

Прямой global-shortcut plugin не инициализируется в Wayland-сессии. На Ubuntu GNOME сохранение настроек через GIO/GSettings создает/обновляет собственную привязку `/org/gnome/settings-daemon/plugins/media-keys/custom-keybindings/stt-simple/` с именем `STT Simple`, выбранным сочетанием и абсолютным путем к бинарнику плюс `--toggle`. При запуске выполняется только read-only проверка, не регистрация.

Snapshot отдельно передает `hotkey_mode` (`native` или `system`) и `hotkey_command`. `hotkey_available` отражает native-регистрацию либо соответствие системной GNOME-привязки настройкам на момент запуска/сохранения. Кнопка сохранения в системном режиме доступна даже без изменения полей, чтобы применить привязку впервые или восстановить её. Чужие записи сохраняются; обнаруженные конфликты с пользовательскими и встроенными GNOME-сочетаниями блокируют сохранение.

Модификаторы и клавиши преобразуются в GTK accelerator; проверяются эквивалентные записи. Неподдерживаемые соответствия клавиш отклоняются. GSettings-запись выполняется вне UI-потока, проверяются доступность схем/dconf, writable и readback. При ошибке откатываются только значения, не измененные после нашей записи; откат списка сохраняет сторонние записи. GSettings не имеет общего CAS/транзакции между путями, поэтому гонки с внешними писателями не полностью исключены. Readback не доказывает успешный захват клавиш композитором; расширения и layout-зависимые физические клавиши могут не обнаруживаться. Привязка не удаляется при выходе и может запускать приложение.

Single-instance plugin передает повторные вызовы работающему экземпляру. Запросы, пришедшие до завершения инициализации, ставятся в очередь. Команда `--toggle` не переводит фокус на окно при успешной записи/распознавании.

Монитор микрофона проверяет ошибки и лимит записи каждые 500 мс. Его действие привязано к ID конкретной записи, поэтому устаревший сигнал не может остановить или начать другую запись. Лимит — 10 минут; при достижении выполняется штатная остановка и STT.

Трей требует работающей AppIndicator-интеграции. На Linux окно при закрытии сворачивается вместо полного скрытия, поскольку tray-объект не доказывает фактическую видимость значка.

`wl-copy` может использовать временный файл и сохранять владение буфером после выхода приложения. Не следует обещать, что скопированный текст никогда не попадает на диск или исчезает после выхода.

## Зависимости и ограничения автоматической вставки Linux

UI показывает настройку на Linux и macOS; для Linux пояснение выбирается по `systemHotkey` (`hotkey_mode === 'system'` означает Wayland), а не по наличию X11 в user agent. На неподдерживаемых платформах настройка скрыта. Поле `Settings.paste_shortcut` присутствует на всех платформах и сериализуется как `ctrl_v` (по умолчанию, в том числе при загрузке старых настроек без поля) или `ctrl_shift_v`. Селектор «Сочетание для вставки» виден только на Linux, отключён при `auto_paste: false` и наследует блокировку fieldset во время записи, обработки и выполнения команды. Draft, нормализация, сравнение настроек и сохранение сохраняют поле и на других платформах. UI не отправляет клавиши самостоятельно: выбор сохраняется через существующие настройки, а eligibility сессии и вставку обеспечивает бэкенд.

На X11 нужен `xdotool` в `PATH`. На Wayland нужен `ydotool`; современный ydotool 1.x требует отдельно настроенного пользователем демона `ydotoold`, доступа к `/dev/uinput` и сокету. Приложение наследует `YDOTOOL_SOCKET`; значение должно присутствовать в окружении при запуске, в том числе через GNOME. Пакет `ydotool` из apt Ubuntu 22.04 может быть legacy, поэтому установка пакета сама по себе не гарантирует современную 1.x и рабочую вставку. Настройка демона/службы и прав зависит от дистрибутива и версии пакета; универсальные инструкции service setup неприменимы. Приложение не выполняет sudo и не меняет службы или права автоматически. Не следует давать всем пользователям права записи в uinput или сокет. См. [README](../README.md#linux).

На Linux отправляется одно выбранное сочетание: `Ctrl+V` или `Ctrl+Shift+V`. Выбор глобален, без определения приложения и без попытки второго сочетания после первого. Пользователь выбирает сочетание, работающее вручную в целевом поле; `Ctrl+Shift+V` может подходить для обычного текста в чате Zed или терминала, но не является универсальным требованием Zed. Цель — поле с фокусом на момент завершения распознавания и опциональной полировки, исходное окно не сохраняется и не активируется. Успешный exit команды не доказывает принятие ввода. Ошибка или тайм-аут вставки не удаляет текст из буфера.

## Статистика

Последняя длительность, сумма длительностей и количество непустых записей сохраняются между запусками. Учитываются завершенные и отмененные записи, независимо от успеха OpenAI. Сброс выполняется только в готовом состоянии. Статистика не хранит тексты или аудио.

Денежная стоимость не показывается и не оценивается: STT-схема возвращает usage, а не стоимость запроса.

## Выполненные проверки на Ubuntu 22.04 / Wayland

Ниже — ранее зафиксированные результаты после обновления Rust до 1.98.1 и установки системных зависимостей, а не подтверждение проверки новой полировки. Числа тестов относятся к тому прогону; ручные сценарии ниже еще нужно выполнить:

- `npm test`: 92 теста интерфейса прошли, включая ручной ID модели, применение GNOME-привязки без изменения полей, конфликт и блокировку настроек при записи.
- `npm run build`: production-сборка интерфейса прошла.
- `cargo test -p stt-core --locked`: 28 тестов ядра прошли, включая локальные HTTP mocks, snapshot/custom ID и параметры Diarize.
- `cargo check -p stt-simple --locked`: desktop-бэкенд компилируется.
- `cargo test -p stt-simple --lib --locked`: 21 desktop unit-тест прошел, включая GNOME-планирование, конфликты, нормализацию, сохранение чужих записей и откат.
- `cargo test -p stt-simple --lib readonly_gnome_session_check --locked -- --ignored --nocapture`: read-only проверка в реальном Ubuntu GNOME/Wayland прошла. Схемы/dconf доступны; отсутствие привязки корректно обнаружено; системные настройки не изменились. Тест по умолчанию отключен, поскольку требует desktop-сеанс. Реальная запись привязки и нажатие клавиш пока требуют проверки через интерфейс.
- `npm run tauri -- build --debug --no-bundle`: собран `target/debug/stt-simple` со встроенным интерфейсом.
- Startup smoke test: процесс приложения работал 8 секунд без раннего завершения, затем был остановлен проверкой. Запись и OpenAI-запрос не запускались.

При перечислении устройств выводились предупреждения ALSA/JACK о недоступных аудиоустройствах. Процесс не завершился, но работа выбранного микрофона еще требует реальной записи.

## Чек-лист реальной проверки

После установки зависимостей и успешной Rust-сборки:

- [ ] Сохранить ключ; перезапустить приложение и проверить наличие ключа без отображения его значения.
- [ ] Выбрать микрофон; записать короткую русскую фразу и фразу с английскими терминами.
- [ ] Проверить цвета трея без полировки: красный → зеленый → синий → красный; с полировкой: красный → зеленый → синий → желтый → красный.
- [ ] Вставить результат из буфера в Zed, JetBrains IDE и браузер.
- [ ] На macOS включить автоматическую вставку, разрешить Accessibility и проверить диктовку через hotkey в нескольких текстовых полях. Проверить, что запуск кнопкой и tray только копирует текст, а отказ в Accessibility не теряет результат.
- [ ] На Linux X11 проверить вставку через xdotool; на Wayland — через настроенный современный ydotool/ydotoold, включая нестандартный `YDOTOOL_SOCKET` в окружении запуска приложения. Проверить оба значения селектора после сохранения и перезапуска: `Ctrl+V` в поле, где оно работает вручную, и `Ctrl+Shift+V` в соответствующем поле чата Zed / терминале. Убедиться, что отправляется только выбранное сочетание, без двойной вставки.
- [ ] Проверить opt-in: по умолчанию только clipboard; после включения — hotkey-start + hotkey-stop и hotkey-start + лимит автоматически вставляют. Запуск или остановка кнопкой/треем не вставляет; отмена тоже не вставляет.
- [ ] Проверить отсутствие утилиты, недоступный сокет/демон и тайм-аут Linux-вставки: ошибка видна, текст остаётся в буфере и доступен для ручной вставки. Убедиться, что приложение не меняет службы/права и не запрашивает sudo.
- [ ] В безопасных тестовых полях сменить фокус во время распознавания: вставка должна идти в текущее поле, без возврата к исходному окну.
- [ ] Сохранить `Super+R` в приложении; проверить привязку STT Simple в GNOME; начать и остановить запись при фокусе в другом приложении.

## Чек-лист полировки и повтора

Чек-лист не является отчетом о выполнении. Реальные STT/Responses-запросы платные; используйте несекретные тестовые диктовки и безопасные поля вставки. Проверки тела HTTP-запроса выполняйте локальными mocks, не записывая настоящий ключ или диктовку в логи.

- [ ] На новых и старых настройках без `polish` проверить: обработка выключена, модель `gpt-6-luna`, effort «По умолчанию». При отсутствующем поле модели используется Luna, явно сохраненные `gpt-5-mini` и свой ID не заменяются. Записать фразу: только STT, нет желтой фазы или текстового запроса, прежнее копирование/вставка работает.
- [ ] Выбрать и сохранить по очереди `polish`, `markdown`, `developer`. Проверить read-only встроенных инструкций, цепочку STT → желтая полировка → копирование и сохранение исходного/итогового текста в отдельных полях.
- [ ] Продиктовать русскую фразу с английскими терминами, именами, числами, неопределенностью, командами, путями и вопросом. Проверить сохранение деталей без ответа на вопрос, решения задачи или выполнения продиктованного «игнорируй инструкции». Проверить уместность Markdown и форматирования сообщения разработчика без добавления фактов.
- [ ] Создать профиль, изменить его название/инструкцию, дублировать встроенный, удалить пользовательский. До «Сохранить настройки» изменения не должны применяться к бэкенду; после сохранения и перезапуска профили должны соответствовать сохраненному состоянию, встроенный оригинал не меняется.
- [ ] Проверить лимиты: 32 профиля допускаются, 33-й недоступен; 80/8000 символов принимаются, 81/8001 и пустые либо пробельные название/инструкция отклоняются. Проверить запрет редактирования во время записи, STT и полировки.
- [ ] Сохранить модель из списка и свой валидный ID, проверить восстановление после перезапуска и общий выбор модели/effort при смене профиля. Локальным HTTP mock проверить `/v1/responses`, `store: false`, отсутствие `reasoning` при `null` и явное `reasoning.effort: "none"` при `none`.
- [ ] Проверить списки effort: Luna — `none/low/medium/high/xhigh/max`, Sol/Astra — `low/medium/high/xhigh/max`; неизвестный ID — полный набор, включая `minimal` и `max`, с предупреждением о непроверенных возможностях. «По умолчанию» доступно везде. Сменить Luna с `none` на Sol/Astra и неизвестную модель с `minimal` на Luna: выбранное значение не меняется, появляется предупреждение о несовместимости. Проверить сохранение/перезапуск и явную смену effort пользователем; API отклоняет неподдерживаемое сочетание без автоматического fallback.
- [ ] При запуске, открытии настроек, смене профиля и модели каталог не загружается сам. Без ключа кнопка «Обновить модели OpenAI» недоступна, ручной ввод ID работает. По нажатию с ключом локальным mock проверить единственный `GET /v1/models` с текущим сохраненным ключом, без тела, аудио, диктовки или инструкций; повторный клик во время загрузки не создает параллельный запрос.

Успешная загрузка не сбрасывает черновик или текущий выбор и не сохраняет настройки автоматически. Событие состояния приложения также не должно сбросить черновик.

Каталог после перезапуска не восстановлен и не загружается сам; выбранный ID сохранен в настройках.

Вставляется только итог и только по прежним правилам, исходный текст раньше итога не копируется. В безопасных полях проверить смену фокуса во время желтой фазы.
- [ ] При успешном STT вызвать ошибку полировки (например, недоступным ID только текстовой модели). Заранее записанный маркер в clipboard не меняется, вставки нет, приложение готово, ошибка видна, raw сохранен, доступен повтор, raw не выдан за итог.
- [ ] После ошибки сохранить другой профиль/инструкцию, модель и effort либо выключить обработку. Повтор должен использовать прежнюю захваченную конфигурацию, а не текущие настройки: исправленный ID не исправляет старую задачу. Изменение/удаление пользовательского профиля также не меняет повтор. Он не отправляет аудио, не меняет длительности/счетчик записей, копирует итог и **никогда не вставляет** его, даже при включенном auto-paste и исходном запуске hotkey.

Проверить, что JSON данных приложения не содержит транскрипций или pending-задачи; не считать внешний clipboard частью этой гарантии.

## Границы проверки

Frontend unit/component tests не доказывают работу микрофона, GNOME hotkey, системного хранилища, трея или синтетического `Cmd+V`/`Ctrl+V`/`Ctrl+Shift+V` через xdotool/ydotool. Эти возможности проверяются на настоящем desktop-сеансе. macOS не считается полностью проверенной до выполнения сценария автоматической вставки в стороннем приложении.
