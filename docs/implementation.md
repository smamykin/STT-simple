# Реализация текущей версии

## Статус платформ

Текущая рабочая платформа — macOS. Backend и frontend TTS реализованы. Реальный платный запрос OpenAI TTS в этой macOS-сессии пока не выполнялся, поэтому end-to-end проверка Speech API остаётся пунктом ручного чек-листа.

Linux runtime для TTS реализован, включая чтение Wayland clipboard через `wl-paste`, запуск через `--toggle-tts` и воспроизведение WAV, но на Linux TTS не проверен. Исторические результаты Ubuntu 22.04 / Wayland ниже относятся к более раннему STT-состоянию проекта и не должны трактоваться как проверка TTS.

## Компоненты

- **Frontend:** React + TypeScript + Vite. Настройки и действия вызывают Rust-команды через Tauri IPC; событие `app-state` обновляет интерфейс. Во время записи снимок состояния запрашивается раз в секунду для таймера. UI содержит отдельные секции диктовки и озвучивания, TTS model/voice/hotkey и disclosure: сгенерированный голос является голосом ИИ, а не человека.
- **Desktop-бэкенд:** Tauri 2. Управляет состояниями, системным треем и горячими клавишами. Изменения состояния сериализованы; события и обновления трея доставляются на главном потоке с актуальным снимком.
- **Захват аудио:** CPAL. Stream создается и закрывается в отдельном потоке; приложение хранит только отправляемый между потоками proxy. Готовность после остановки означает, что поток подтвердил закрытие микрофона.
- **Воспроизведение:** rodio. Полученный WAV остаётся в `Vec<u8>`, декодируется через `Cursor<Vec<u8>>` и передаётся worker-потоку. Подготовка плеера происходит беззвучно, playback начинается отдельной командой. Остановка считается завершённой только после подтверждения освобождения sink/stream. Временные аудиофайлы не создаются.
- **Ядро:** отдельный crate `stt-core`, не зависящий от GUI. STT WAV — mono PCM16, 16 кГц; длительность вычисляется до ресемплинга по числу аудиокадров. Ядро содержит настройки и OpenAI-клиент для STT/TTS.
- **Сеть STT:** reqwest с Rustls, фиксированный endpoint `https://api.openai.com/v1/audio/transcriptions`, multipart WAV, JSON-результат. Для Diarize отправляется `chunking_strategy=auto`, приложение использует только поле `text`.
- **Сеть TTS:** тот же клиент отправляет JSON на фиксированный endpoint `https://api.openai.com/v1/audio/speech`: `model`, `voice`, исходный неусечённый `input`, `response_format="wav"`. По умолчанию используются `gpt-4o-mini-tts` и `marin`. Пустой текст и ввод длиннее 4096 Unicode-символов отклоняются до сети; потоковый WAV-ответ ограничен 64 MiB.
- **Общие сетевые свойства:** redirects запрещены, timeout — 120 секунд, пользовательский endpoint не поддерживается. UI и Rust проверяют формат custom model/voice IDs без жёсткого allowlist; доступность и совместимость определяет OpenAI. Сырые тела ошибок пользователю не показываются.
- **Ключ:** keyring 3 — Secret Service на Linux, Keychain на macOS. Ключ отсутствует в JSON состояния/настроек; временные строки ключа в бэкенде оборачиваются в `Zeroizing` там, где контракт владения это позволяет.
- **Буфер:** `wl-copy`/`wl-paste` на Wayland; Tauri clipboard plugin на других системах. Операции сериализованы. Ручное копирование результата разрешено только в готовом состоянии. Wayland subprocess ограничены timeout; при зависании завершается вся группа.
- **Автоматическая вставка:** на macOS после успешного копирования CoreGraphics отправляет `Cmd+V`. Вставка вооружается только при старте записи глобальным STT hotkey и выполняется при остановке тем же hotkey или по лимиту; кнопка и tray её не запускают. Accessibility запрашивается при сохранении включённой настройки и повторно проверяется перед вставкой. При ошибке текст остаётся в clipboard.
- **Настройки/статистика:** JSON в app data directory. Запись через временный соседний файл и rename; после commit ошибка синхронизации каталога возвращается как предупреждение, не как отказ сохранения. TTS audio и текстовая история в этот JSON не входят.

## TTS flow и взаимное исключение операций

1. `toggle_speech` принимается только в `idle`, `synthesizing` или `playing`.
2. В `idle` backend создаёт TTS session, переводит snapshot в `synthesizing`, читает и валидирует clipboard, загружает API key и запускает OpenAI synthesis.
3. После успешного ответа WAV готовится в RAM-плеере, затем состояние меняется на `playing` и начинается вывод.
4. Повторный вызов в `synthesizing` или `playing` посылает cancellation/stop и не возвращает приложение в `idle`, пока подготовка или playback не подтвердят освобождение ресурсов. Остановка плеера ограничена внутренним timeout 3 секунды; при отсутствии подтверждения новая операция блокируется с ошибкой.
5. TTS-вызов во время `recording`, `transcribing` или `polishing` игнорируется/недоступен в UI и tray.
6. STT-вызов во время TTS сначала вызывает полную остановку TTS и ждёт её завершения. Только после этого запускается обычный путь записи и открывается микрофон.

`Phase` включает `idle`, `recording`, `transcribing`, зарезервированный `polishing`, а также `synthesizing` и `playing`. Tray показывает текстовый статус и цвета: красный, зелёный, синий, жёлтый и фиолетовый соответственно. Его TTS action переключается между «Озвучить буфер» и «Остановить озвучивание»; STT action во время TTS подписан «Остановить озвучивание и начать запись».

## Горячие клавиши

### macOS и X11

Обе комбинации регистрируются через native global-shortcut plugin. Backend default для TTS — `Control+Super+A`; UI macOS форматирует его как `Ctrl+Cmd+A`, не изменяя сохранённое значение. STT default macOS аналогично хранится как `Control+Super+R` и показывается как `Ctrl+Cmd+R`. Настройки запрещают эквивалентные STT/TTS-комбинации.

### Ubuntu 22.04 / GNOME 42 / Wayland

Прямой global-shortcut plugin не инициализируется в Wayland-сессии. Для STT сохранение настроек через GIO/GSettings создаёт/обновляет собственную привязку `/org/gnome/settings-daemon/plugins/media-keys/custom-keybindings/stt-simple/` с именем `STT Simple`, выбранным сочетанием и абсолютным путём к бинарнику плюс `--toggle`. При запуске выполняется только read-only проверка, не регистрация.

Автоматическая GNOME-регистрация остаётся только для STT. Для TTS snapshot отдаёт отдельную команду текущего бинарника с `--toggle-tts` и сообщение о необходимости вручную назначить её в системных сочетаниях. Это применимо и к другим Wayland-окружениям.

Snapshot отдельно передаёт `hotkey_mode` (`native` или `system`), STT `hotkey_command`/статус и TTS `tts_hotkey_command`/статус. `hotkey_available` отражает native-регистрацию либо соответствие системной GNOME STT-привязки настройкам на момент запуска/сохранения. На Wayland `tts_hotkey_available` остаётся false, потому что ручную системную привязку приложение не может подтвердить.

Кнопка сохранения в системном режиме доступна даже без изменения полей, чтобы применить STT-привязку впервые или восстановить её. Чужие записи сохраняются; обнаруженные конфликты с пользовательскими и встроенными GNOME-сочетаниями блокируют сохранение STT-настройки.

Модификаторы и клавиши преобразуются в GTK accelerator; проверяются эквивалентные записи. Неподдерживаемые соответствия клавиш отклоняются. GSettings-запись выполняется вне UI-потока, проверяются доступность схем/dconf, writable и readback. При ошибке откатываются только значения, не изменённые после нашей записи; откат списка сохраняет сторонние записи. GSettings не имеет общего CAS/транзакции между путями, поэтому гонки с внешними писателями не полностью исключены. Readback не доказывает успешный захват клавиш композитором; расширения и layout-зависимые физические клавиши могут не обнаруживаться. Привязка не удаляется при выходе и может запускать приложение.

Single-instance plugin передаёт повторные вызовы работающему экземпляру. Запросы, пришедшие до завершения инициализации, ставятся в очередь. `--toggle` запускает STT, `--toggle-tts` запускает TTS; успешные фоновые действия не переводят фокус на окно.

Монитор микрофона проверяет ошибки и лимит записи каждые 500 мс. Его действие привязано к ID конкретной записи, поэтому устаревший сигнал не может остановить или начать другую запись. Лимит — 10 минут; при достижении выполняется штатная остановка и STT.

Трей требует работающей AppIndicator-интеграции. На Linux окно при закрытии сворачивается вместо полного скрытия, поскольку tray-объект не доказывает фактическую видимость значка.

`wl-copy` может использовать временный файл и сохранять владение буфером после выхода приложения. Clipboard в целом не является приватным хранилищем: системные менеджеры истории и другие приложения могут сохранять текст. Нельзя обещать, что скопированный текст никогда не попадёт на диск или исчезнет после выхода.

## Приватность и стоимость

- STT отправляет в OpenAI аудио, модель и API key.
- TTS отправляет в OpenAI clipboard text, модель, голос и API key.
- Использование API оплачивается аккаунтом OpenAI пользователя. Приложение не показывает и не утверждает конкретную цену.
- STT audio до отправки и TTS WAV response/playback находятся в RAM. STT Simple не создаёт temp audio files и не ведёт постоянную историю аудио, транскрипций или TTS.
- На диск сохраняются настройки без ключа и агрегированная статистика записей. API key хранится в системном хранилище секретов.

## Статистика

Последняя длительность, сумма длительностей и количество непустых записей сохраняются между запусками. Учитываются завершенные и отмененные записи, независимо от успеха OpenAI. Сброс выполняется только в готовом состоянии. Статистика не хранит тексты или аудио и не учитывает TTS.

Денежная стоимость не показывается и не оценивается ни для STT, ни для TTS.

## Исторические проверки на Ubuntu 22.04 / Wayland — только STT

Следующие результаты были получены до реализации TTS. Они сохранены как исторические сведения о STT и инфраструктуре и **не подтверждают работу Linux TTS**.

После обновления Rust до 1.98.1 и установки системных зависимостей:

- `npm test`: 92 теста интерфейса прошли, включая ручной ID STT-модели, применение GNOME STT-привязки без изменения полей, конфликт и блокировку настроек при записи.
- `npm run build`: production-сборка интерфейса прошла.
- `cargo test -p stt-core --locked`: 28 тестов ядра прошли, включая локальные HTTP mocks, snapshot/custom STT ID и параметры Diarize.
- `cargo check -p stt-simple --locked`: тогдашний desktop-бэкенд компилировался.
- `cargo test -p stt-simple --lib --locked`: 21 тогдашний desktop unit-тест прошел, включая GNOME-планирование, конфликты, нормализацию, сохранение чужих записей и откат.
- `cargo test -p stt-simple --lib readonly_gnome_session_check --locked -- --ignored --nocapture`: read-only проверка в реальном Ubuntu GNOME/Wayland прошла. Схемы/dconf доступны; отсутствие STT-привязки корректно обнаружено; системные настройки не изменились. Реальная запись привязки и нажатие клавиш оставались ручной проверкой.
- `npm run tauri -- build --debug --no-bundle`: был собран `target/debug/stt-simple` со встроенным интерфейсом.
- Startup smoke test: процесс приложения работал 8 секунд без раннего завершения, затем был остановлен проверкой. Запись и OpenAI-запрос не запускались.

При перечислении устройств выводились предупреждения ALSA/JACK о недоступных аудиоустройствах. Процесс не завершился, но работа выбранного микрофона требовала реальной записи. Ни один пункт этого раздела не проверял `--toggle-tts`, `wl-paste`, OpenAI Speech API или Linux playback.

## Чек-лист ручной проверки на macOS

В этой сессии macOS является рабочей платформой, но реальный платный OpenAI TTS-запрос ещё не выполнялся. Для полной проверки:

- [ ] Запустить актуальную сборку на macOS; сохранить ключ, перезапустить приложение и проверить наличие ключа без отображения его значения.
- [ ] Выбрать микрофон; записать короткую русскую фразу и фразу с английскими терминами.
- [ ] Проверить STT tray flow и цвета: красный → зеленый → синий → красный.
- [ ] Вставить результат из буфера в Zed, JetBrains IDE и браузер.
- [ ] Включить автоматическую вставку, разрешить Accessibility и проверить диктовку через STT hotkey в нескольких текстовых полях. Убедиться, что запуск кнопкой и tray только копирует текст, а отказ в Accessibility не теряет результат.
- [ ] Проверить отображение default hotkeys: STT `Ctrl+Cmd+R`, TTS `Ctrl+Cmd+A`, при сохранённых backend-значениях `Control+Super+R` и `Control+Super+A`.
- [ ] Скопировать короткий текст и впервые выполнить реальный платный TTS-запрос с default `gpt-4o-mini-tts`/`marin`; подтвердить disclosure об AI voice, переходы `idle → synthesizing → playing → idle`, звук и TTS status/action в tray.
- [ ] Во время `synthesizing` повторно нажать TTS hotkey: запрос должен быть отменён без последующего звука. Во время `playing` повторно нажать hotkey: звук должен остановиться.
- [ ] Во время TTS запустить STT кнопкой, hotkey и tray: playback должен полностью остановиться до открытия микрофона; параллельного вывода и записи быть не должно.
- [ ] Во время записи и распознавания проверить, что TTS button/hotkey/tray action недоступны и не запускают запрос.
- [ ] Очистить clipboard и проверить TTS: должно появиться сообщение «Буфер обмена пуст или содержит только пробелы», OpenAI-запрос и playback отсутствуют. Повторить с одними пробелами.
- [ ] Поместить в clipboard 4097 Unicode-символов: должно появиться сообщение о лимите 4096, без OpenAI-запроса. Проверить успешную валидацию ровно 4096 Unicode-символов подходящим тестовым запросом только если приемлемы стоимость и длительность.
- [ ] Указать заведомо неверный по формату TTS model ID, например `bad/model`, и voice ID, например `bad voice`: сохранение должно быть отклонено локально с отдельным сообщением, без запроса.
- [ ] Указать форматно допустимый, но недоступный model/voice ID: OpenAI должен вернуть безопасную ошибку о модели или голосе без сырого response body и содержимого clipboard.
- [ ] Ввести API key с пробелом или переносом строки: сохранение должно быть отклонено локально с подсказкой скопировать ключ целиком. Затем сохранить форматно допустимый, но недействительный ключ и запустить TTS: должна появиться отдельная ошибка авторизации без утечки ключа или clipboard text.
- [ ] Проверить отсутствие temp audio files и постоянной TTS-истории: после окончания/остановки в UI и app-data должны остаться только обычные настройки/статистика, без WAV и списка озвучиваний.
- [ ] Проверить ошибку устройства вывода, если её можно безопасно воспроизвести: приложение должно вернуться в готовность с понятным сообщением.
- [ ] Отменить STT-запись: буфер не меняется, OpenAI-запрос отсутствует, длительность учтена.
- [ ] Отключить микрофон при записи: ошибка показана, приложение возвращается к готовности после закрытия stream.
- [ ] Проверить STT API-ошибку с недействительным ключом: буфер не меняется, статистика длительности сохраняется.
- [ ] Проверить ошибку копирования: текст остается в окне, доступна повторная попытка.
- [ ] Проверить быстрые повторные действия: нет параллельных записей/TTS sessions, старого текста в буфере или неожиданного перезапуска операции.
- [ ] Перезапустить приложение и проверить статистику; затем выполнить ее сброс. Убедиться, что TTS не изменяет статистику записей.

## Чек-лист Linux TTS

Linux TTS runtime реализован, но не проверен. Не переносите сюда результаты старых Ubuntu STT-проверок как подтверждение TTS.

- [ ] Установить `wl-clipboard`, проверить чтение text/plain через `wl-paste` и сообщения для пустого/нетекстового/слишком большого clipboard.
- [ ] Вручную назначить TTS hotkey на показанную команду `stt-simple --toggle-tts`; убедиться, что сохранение настроек приложения не создаёт для неё GNOME-привязку автоматически.
- [ ] Проверить single-instance запуск `--toggle-tts`, OpenAI TTS, WAV playback, повторную остановку и освобождение ALSA/Pulse/PipeWire output.
- [ ] Повторить проверки взаимного исключения STT/TTS и tray status/action.

## Границы проверки

Frontend unit/component tests и Rust unit tests не доказывают работу микрофона, native/Wayland hotkey, системного хранилища, clipboard, трея, реального OpenAI Speech API, устройства вывода или синтетического `Cmd+V`. Эти возможности проверяются в настоящем desktop-сеансе.

Строгая совместимость проекта с Rust 1.77.2 не заявляется: несмотря на `rust-version` в manifests, текущий lockfile включает зависимости, которым нужен более новый toolchain и Edition 2024. Для сборки используйте актуальный совместимый Rust stable.
