# Основные требования

## Цель и платформы

Локальное приложение для голосового ввода и озвучивания текста в любых приложениях с использованием собственного OpenAI API key, без подписки на отдельный сервис диктовки или TTS.

- Стек: Tauri + Rust.
- Текущая рабочая платформа: macOS.
- Linux runtime для STT и TTS реализован. TTS на Linux пока не проверен в реальном desktop-сеансе; исторические проверки Ubuntu/Wayland подтверждают только прежний STT-сценарий.

## Основные сценарии

### Диктовка

1. Пользователь нажимает глобальную горячую клавишу — начинается запись микрофона.
2. Повторное нажатие останавливает запись.
3. Приложение отправляет аудио в OpenAI API для speech-to-text.
4. Результат speech-to-text без дополнительной обработки сохраняется в буфере обмена.
5. На macOS при включённой настройке результат диктовки через hotkey автоматически вставляется в активное поле; иначе пользователь вставляет текст вручную.
6. Приложение возвращается в состояние готовности.

### Озвучивание текста

1. Пользователь копирует текст в системный буфер обмена.
2. Пользователь нажимает глобальный TTS hotkey или выбирает действие в окне/трее.
3. Приложение читает текст из буфера, проверяет его и отправляет вместе с API key в OpenAI `POST /v1/audio/speech`.
4. Приложение запрашивает WAV и воспроизводит его из RAM через системное устройство вывода.
5. Сгенерированный голос явно обозначается как голос ИИ, а не человека.
6. Повторное действие во время синтеза или воспроизведения останавливает текущий TTS и возвращает приложение в готовность после освобождения аудиоустройства.

## Функциональные требования

- Два разных настраиваемых глобальных hotkey, работающих без фокуса на окне приложения:
  - STT по умолчанию на Linux: `Super+R` (Win+R).
  - STT по умолчанию на macOS: backend `Control+Super+R`, UI `Ctrl+Cmd+R`.
  - TTS по умолчанию на всех платформах хранится как `Control+Super+A`; UI macOS показывает `Ctrl+Cmd+A`.
  - При конфликте или недоступности сочетания сообщить пользователю и позволить сменить его. STT и TTS hotkey не могут обозначать одно сочетание.
- Выбор микрофона.
- Индикатор в системном трее (на macOS — в строке меню), отражающий состояние приложения:
  - **Зеленый:** идет запись (`recording`).
  - **Синий:** идет распознавание речи (`transcribing`), без перевода на другой язык.
  - **Желтый:** создаётся речь (`synthesizing`); этот цвет также зарезервирован для будущей дополнительной обработки (`polishing`).
  - **Фиолетовый:** воспроизводится сгенерированная речь (`playing`).
  - **Красный:** приложение готово к следующему запуску (`idle`). Это нормальное состояние, а не обозначение ошибки.
  - Состояние также указывается текстом в меню/подсказке, чтобы не полагаться только на цвет.
- Трей содержит отдельное действие TTS: «Озвучить буфер» либо «Остановить озвучивание» в зависимости от состояния.
- Распознавание русской и английской речи, включая технические термины.
- Результат STT копируется в буфер обмена для ручной вставки в Zed, JetBrains IDE, браузеры и другие приложения.
- На macOS доступна опциональная автоматическая вставка через системное `Cmd+V`; она применяется только к диктовке, начатой hotkey, и требует Accessibility.
- Только OpenAI API, без дополнительных провайдеров и пользовательского API endpoint.
- Настройки OpenAI API key, STT-модели, TTS-модели и голоса.
- TTS использует фиксированный endpoint `/v1/audio/speech`, `response_format="wav"`, модель по умолчанию `gpt-4o-mini-tts` и голос по умолчанию `marin`.
- Пользовательские ID STT/TTS-модели и голоса разрешены после проверки формата. Проверка формата не подтверждает существование, доступность или совместимость ID; это определяет OpenAI.
- TTS принимает непустой текст длиной не более 4096 Unicode-символов. WAV-ответ ограничен 64 MiB. Сетевой timeout — 120 секунд.
- Дополнительная обработка текста и вызовы текстовой модели отсутствуют.
- Возможность отменить запись; понятные ошибки при проблемах с микрофоном, выводом звука, сетью, API, буфером, ключом, моделью или голосом.
- При ошибке распознавания не перезаписывать буфер обмена; после завершения запроса вернуть приложение в состояние готовности и отдельно показать ошибку.
- При пустом или состоящем только из пробелов буфере TTS не отправляет запрос и сообщает, что буфер пуст. При тексте длиннее 4096 Unicode-символов запрос не отправляется и предлагается сократить текст.
- Во время `recording`, `transcribing` или `polishing` TTS недоступен.
- Запуск STT во время `synthesizing` или `playing` сначала отменяет синтез/останавливает playback, дожидается освобождения ресурса вывода и только затем открывает микрофон.

## Статистика

- Показывать длительность последней записи и суммарную длительность записей в минутах и секундах.
- Длительность измерять локально по записанному аудио, независимо от успешности запроса к API.
- Сохранять агрегированную статистику между запусками; предусмотреть сброс. Учитывать непустые завершенные и отмененные записи.
- Не показывать и не рассчитывать денежную стоимость STT или TTS. Использование API оплачивается аккаунтом OpenAI пользователя; конкретная цена зависит от его условий и OpenAI.
- Статистика длительности не требует хранения аудио, истории транскрипций или истории TTS.

## Ограничения и безопасность

- На Ubuntu/GNOME/Wayland системная привязка STT вызывает бинарник с `--toggle`. Сохранение настроек в приложении создаёт/обновляет только собственную STT-привязку STT Simple; чужие сочетания не перезаписываются. При запуске привязка проверяется без изменения системных настроек. Конфликты с известными GNOME-сочетаниями показываются как ошибка; перехват сторонними расширениями не гарантированно обнаруживается.
- Автоматическая GNOME-регистрация с `--toggle` остаётся только для STT. TTS hotkey на Wayland пользователь назначает вручную в системных настройках на команду текущего бинарника с `--toggle-tts`.
- На macOS и X11 оба hotkey регистрируются нативно приложением.
- Видимость и обновление цветного значка трея нужно проверить на целевом Linux: поддержка зависит от окружения и расширений рабочего стола. На Linux закрытие окна сворачивает его, а не скрывает в потенциально невидимый трей.
- Автоматическая вставка поддерживается только на macOS. На Wayland она остаётся отложенной. Целевым считается активное поле на момент завершения распознавания; приложение не сохраняет и не активирует исходное окно.
- На macOS требуется разрешение на микрофон и, для автоматической вставки, Accessibility.
- API key хранится в системном хранилище секретов и не попадает в исходники, JSON настроек или логи.
- Для STT в OpenAI передаются аудио, модель и API key. Для TTS передаются текст из буфера, модель, голос и API key. Использование API оплачивается пользователем отдельно.
- Записанное аудио, WAV-ответ TTS и playback хранятся только в RAM. Приложение не создаёт временные аудиофайлы и не ведёт постоянную историю транскрипций или озвучивания.
- Буфер обмена не является приватным хранилищем: другие приложения и менеджеры истории могут прочитать или сохранить его содержимое. На Wayland `wl-copy` может использовать собственный временный файл независимо от STT Simple.
- Максимальная длительность записи — 10 минут; на лимите выполняется остановка и распознавание.
- Ошибки API не должны содержать сырой ответ OpenAI, API key, аудио, текст буфера или транскрипцию.

## Границы текущей версии

Текущая версия включает диктовку целой фразы, транскрипцию через OpenAI после остановки, озвучивание текста из буфера через OpenAI, отдельные hotkey STT/TTS, индикатор и действия трея, буфер обмена и статистику длительности записей.

Автоматическая вставка на Wayland, дополнительная обработка текста, потоковое распознавание, пользовательские профили, словарь терминов и постоянная история не входят в текущую версию.
