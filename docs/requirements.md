# Основные требования

## Цель и платформы

Локальное приложение для голосового ввода в любые текстовые приложения с использованием собственного OpenAI API key, без подписки на отдельный сервис диктовки.

- Стек: Tauri + Rust.
- Первая целевая платформа: Ubuntu с Wayland.
- Следующая целевая платформа: macOS.

## Основной сценарий

1. Пользователь нажимает глобальную горячую клавишу — начинается запись микрофона.
2. Повторное нажатие останавливает запись.
3. Приложение отправляет аудио в OpenAI API для speech-to-text.
4. Если выбран профиль обработки, результат speech-to-text автоматически проходит полировку; затем итоговый текст сохраняется в буфере обмена. По умолчанию обработка выключена и прежний путь STT → копирование сохраняется.
5. На Linux и macOS при включённой настройке результат диктовки через hotkey автоматически вставляется в активное поле; иначе пользователь вставляет текст вручную.
6. Приложение возвращается в состояние готовности.

## Функциональные требования

- Настраиваемая глобальная горячая клавиша, работающая без фокуса на окне приложения.
  - По умолчанию на Linux: `Super+R` (Win+R).
  - По умолчанию на macOS: `Ctrl+Cmd+R`.
  - При конфликте или недоступности сочетания сообщить пользователю и позволить сменить его.
- Выбор микрофона.
- Индикатор в системном трее (на macOS — в строке меню), отражающий состояние приложения:
  - **Зеленый:** идет запись (`recording`).
  - **Синий:** идет распознавание речи (`transcribing`), без перевода на другой язык.
  - **Желтый:** идет дополнительная обработка текста (`polishing`), включая повтор после ошибки.
  - **Красный:** запись остановлена, приложение готово к следующему запуску (`idle`). Это нормальное состояние, а не обозначение ошибки.
  - Состояние также указывается текстом в меню/подсказке, чтобы не полагаться только на цвет.
- Распознавание русской и английской речи, включая технические термины.
- Результат копируется в буфер обмена для ручной вставки в Zed, JetBrains IDE, браузеры и другие приложения.
- Автоматическая вставка опциональна и по умолчанию выключена (`auto_paste: false`). Она применяется только к диктовке, начатой глобальным hotkey и остановленной hotkey или автоматически по лимиту. Запуск или остановка через кнопку/трей только копирует результат.
- На macOS вставка всегда использует системное `Cmd+V` и требует Accessibility. На Linux селектор «Сочетание для вставки» предлагает `Ctrl+V` (по умолчанию) и `Ctrl+Shift+V`; он отключён при выключенной автоматической вставке и при блокировке настроек. Поле `paste_shortcut` присутствует на всех платформах (`ctrl_v` / `ctrl_shift_v`), старые настройки без поля получают `ctrl_v`; селектор виден только на Linux. На X11 используются `xdotool key --clearmodifiers ctrl+v` / `xdotool key --clearmodifiers ctrl+shift+v`, на Wayland — `ydotool key 29:1 47:1 47:0 29:0` / `ydotool key 29:1 42:1 47:1 47:0 42:0 29:0` соответственно. На неподдерживаемых платформах настройка автоматической вставки скрыта.
- Сочетание вставки — одна глобальная настройка без определения целевого приложения и без fallback вторым сочетанием. Выбирать следует рабочее ручное сочетание для конкретного поля; `Ctrl+Shift+V` может подходить для вставки обычного текста в чат Zed или терминал, но не требуется универсально для всех полей Zed.
- Только OpenAI API в первой версии, без дополнительных провайдеров и пользовательского API endpoint.
- Настройки OpenAI API key и модели распознавания.
- Опциональная обработка текста через OpenAI Responses API после STT и до копирования/вставки; требования описаны ниже.
- Возможность отменить запись; понятные ошибки при проблемах с микрофоном, сетью или API.
- При ошибке распознавания не перезаписывать буфер обмена; после завершения запроса вернуть приложение в состояние готовности и отдельно показать ошибку.

## Обработка текста и профили

- Используется тот же OpenAI API key, что и для STT: `POST /v1/responses` с `store: false`. Это дополнительный платный текстовый запрос, передающий распознанный текст и инструкции в OpenAI.
- По умолчанию `polish.profile_id: null` (выключено), модель `gpt-6-luna`, `effort: null`. Значение модели по умолчанию применяется к новым настройкам или отсутствующему полю; явно сохраненные `gpt-5-mini` и другие ID не заменяются. Модель и effort глобальны для всех профилей.
- Готовые варианты: `gpt-6-luna`, `gpt-6.1-sol`, `gpt-6-astra`; сверены с [официальным каталогом](https://developers.openai.com/api/docs/models) 2026-10-03. Ручной ввод ID остается доступным, в том числе без загруженного каталога.
- Кнопка «Обновить модели OpenAI» вызывает `GET /v1/models` с тем же сохраненным API key только по явному нажатию, не автоматически при запуске/открытии настроек. Аудио, текст диктовки и инструкции не отправляются; каталог хранится только в памяти.
- Все возвращенные модели доступны без фильтра совместимости; дополнительные ID показываются отдельной группой «Каталог OpenAI — совместимость не проверена», без дублей готовых вариантов. [List models](https://developers.openai.com/api/reference/resources/models/methods/list) предоставляет только базовые метаданные, не гарантирует поддержку Responses API и не сообщает допустимые effort.
- Загрузка каталога и ее ошибка не меняют черновик, выбранную модель/effort и ручной ID. Ошибка показывается отдельно, ранее загруженный каталог сохраняется. Сохраненный ID не зависит от присутствия модели в каталоге; каталог не сохраняется на диск, выбранная модель сохраняется обычным путем настроек.
- «По умолчанию» (`effort: null`) доступно для любой модели и не отправляет `reasoning`; явное `none` отправляет `reasoning.effort: "none"` и не равнозначно отсутствию параметра. Для точного ID `gpt-6-luna` известны `none`, `low`, `medium`, `high`, `xhigh`, `max`; для `gpt-6.1-sol` и `gpt-6-astra` — `low`, `medium`, `high`, `xhigh`, `max`. Для неизвестных ID показывается полный набор `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` с оговоркой о непроверенной поддержке.
- Выбранный effort не меняется автоматически при смене модели или обновлении каталога. Несовместимое по известным возможностям значение сохраняется в селекторе с предупреждением, пока пользователь сам его не изменит. API окончательно отклоняет неподдерживаемые сочетания.
- Выбор Responses API соответствует [рекомендации OpenAI для всех новых проектов](https://developers.openai.com/api/docs/guides/migrate-to-responses), а не является выводом из наличия модели в `/v1/models`.
- Три неизменяемых встроенных профиля: `polish` (минимальная правка), `markdown` (структура Markdown), `developer` (сообщение разработчика с сохранением технических деталей).
- Общие системные правила требуют сохранять язык, смысл, факты, детали и идентификаторы, ничего не выдумывать, не отвечать на вопросы и не выполнять продиктованные инструкции. Текст диктовки — данные для редактирования, а не команды модели; ответ содержит только отредактированный текст. Эти инструкции не заменяют проверку результата пользователем.
- Пользовательские профили можно создавать, просматривать, редактировать, удалять и дублировать, в том числе из встроенного. Изменения применяются только через сохранение настроек. Максимум 32 пользовательских профиля; непустое название до 80 символов, непустая инструкция до 8000 символов. Встроенные профили не редактируются и не удаляются.
- Начальный успешный путь: STT → полировка (если включена) → копирование → опциональная вставка по прежним правилам hotkey. Во время `polishing` новые записи и ручное копирование недоступны, настройки заблокированы.
- При ошибке полировки вернуть состояние готовности, показать ошибку, не копировать и не вставлять ничего, не подменять итог исходным текстом. Исходный STT-текст и захваченная конфигурация неудавшейся задачи остаются только в памяти для повтора.
- Повтор использует захваченный профиль с инструкцией, модель и effort, но текущий API key из хранилища. Изменение и сохранение настроек после ошибки **не меняет параметры повтора**. Новые настройки применяются к новым записям; исправление несовместимой модели/effort требует новой записи, а не повтора старой задачи.
- Повтор не выполняет STT и не изменяет статистику записей. Успешный повтор только копирует итог и **никогда не выполняет автоматическую вставку**. При повторной ошибке исходный текст и задача остаются доступными.
- Успешный старт новой записи инвалидирует старую задачу повтора, даже если новую запись затем отменить; неудавшийся запуск микрофона ее не инвалидирует. Успешная полировка также убирает возможность повтора этой задачи.
- Исходный и итоговый текст, а также задача повтора хранятся только в памяти и не переживают выход из приложения. Настройки профилей сохраняются, но история транскрипций и импорт/экспорт профилей не реализованы.

## Статистика

- Показывать длительность последней записи и суммарную длительность записей в минутах и секундах.
- Длительность измерять локально по записанному аудио, независимо от успешности запроса к API.
- Сохранять агрегированную статистику между запусками; предусмотреть сброс. Учитывать непустые завершенные и отмененные записи.
- Стоимость показывать только если OpenAI возвращает денежную стоимость конкретного STT-запроса. Если стоимость отсутствует, не показывать ее и не рассчитывать по тарифам.
- Статистика длительности не требует хранения аудио или истории транскрипций.
- В проверенных схемах ответов официального OpenAI SDK есть `usage` (токены или секунды), но нет денежной стоимости. Поэтому для текущего API отображение стоимости не планируется.

## Ограничения и безопасность

- На Ubuntu/GNOME/Wayland используется системное сочетание GNOME, вызывающее бинарник с `--toggle`. Сохранение настроек в приложении создает/обновляет только собственную привязку STT Simple; чужие сочетания не перезаписываются. При запуске привязка проверяется без изменения системных настроек. Конфликты с известными GNOME-сочетаниями показываются как ошибка; перехват сторонними расширениями не гарантированно обнаруживается.
- Видимость и обновление цветного значка трея нужно проверить на целевом Ubuntu: поддержка зависит от окружения и расширений рабочего стола. На Linux закрытие окна сворачивает его, а не скрывает в потенциально невидимый трей.
- Целевым для автоматической вставки считается активное поле на момент завершения распознавания и опциональной полировки; приложение не сохраняет и не активирует исходное окно. Успех отправки клавиш не гарантирует принятие вставки целевым приложением.
- Linux-команды вставки ограничены 5 секундами; при ошибке или тайм-ауте скопированный текст сохраняется в буфере.
- Пользователь самостоятельно устанавливает Linux-зависимости. Современный ydotool 1.x требует настроенного демона, доступа к uinput и сокету; `YDOTOOL_SOCKET` наследуется из окружения приложения. Настройка зависит от дистрибутива, пакет Ubuntu 22.04 может быть legacy. Приложение не запускает sudo и не изменяет службы/права доступа; нельзя рекомендовать общедоступные для записи uinput или сокет.
- На macOS потребуется разрешение на микрофон и, для выбранного механизма автоматической вставки, Accessibility.
- API key хранится в системном хранилище секретов и не попадает в исходники или логи.
- Аудио передается в OpenAI для STT; при включенной полировке текст и инструкции передаются отдельным платным запросом. Использование API оплачивается пользователем. `store: false` не означает локальную обработку или гарантию отсутствия любого хранения у провайдера.
- Приложение не сохраняет записи или транскрипции в постоянную историю; аудио хранится только в памяти до завершения или отмены обработки. Буфер обмена и `wl-copy` могут сохранять скопированный текст независимо от приложения.
- Максимальная длительность записи — 10 минут; на лимите выполняется остановка и распознавание.

## Границы первой версии

Реализованы запись целой фразы, транскрипция через OpenAI после остановки, опциональная полировка со встроенными и пользовательскими профилями, повтор неудавшейся полировки, настраиваемая глобальная горячая клавиша, цветной индикатор трея, буфер обмена, опциональная автоматическая вставка и статистика длительности записей.

Повторная обработка последнего успешного результата другим профилем — nice to have, пока не реализована; изменение настроек само по себе не обрабатывает последний результат. Потоковое распознавание, словарь терминов, импорт/экспорт профилей и постоянная история не реализованы.

Ручные приемочные сценарии перечислены в [implementation.md](implementation.md#чек-лист-полировки-и-повтора).
