# STT Simple

Настольная диктовка на Tauri 2 + Rust с собственным OpenAI API key. Первая целевая система — Ubuntu/Wayland. В коде предусмотрены macOS Keychain, системный hotkey и разрешение на микрофон, но macOS еще требует отдельной сборки и проверки.

## Первая версия

- Одно нажатие начинает запись, повторное останавливает и отправляет аудио в OpenAI STT.
- Результат без полировки копируется в буфер обмена; на Linux и macOS его можно автоматически вставлять в активное поле после диктовки через hotkey.
- Цветной значок трея: зеленый — запись, синий — распознавание, красный — готовность. Желтый зарезервирован для будущей полировки.
- Выбор микрофона, модели и горячей клавиши.
- Длительность последней записи, суммарное время и количество записей; статистику можно сбросить.
- Отмена записи без отправки аудио. В статистику входят непустые завершенные и отмененные записи, включая записи с ошибкой API.
- Лимит одной записи — 10 минут; на лимите запись автоматически отправляется на распознавание.
- Стоимость не показывается: STT-ответ содержит usage, но не денежную стоимость запроса. Приложение не рассчитывает цену самостоятельно.

## Подготовка Ubuntu 22.04

Нужны Node.js 22.12+ либо 24+, актуальный Rust stable и системные библиотеки. Первый запуск установки зависимостей и Cargo использует интернет и может занять несколько минут.

```sh
rustup update stable
sudo apt update
sudo apt install build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev libasound2-dev libdbus-1-dev patchelf wl-clipboard
```

Для секретов используется GNOME Keyring / Secret Service. В обычной Ubuntu GNOME он уже установлен; хранилище должно быть запущено и разблокировано. Не используйте `sudo` для запуска приложения, npm или Cargo.

В каталоге проекта:

```sh
npm ci
npm run tauri -- dev
```

Быстрая debug-сборка со встроенным интерфейсом, без отдельного Vite-сервера:

```sh
npm run tauri -- build --debug --no-bundle
./target/debug/stt-simple
```

Если бинарник уже собран, достаточно второй команды.

Сборка `.deb`:

```sh
npm run tauri -- build --bundles deb
```

Готовые пакеты находятся в `target/release/bundle/deb/`. Установка пакета выполняется отдельно. Собранный исполняемый файл — `target/release/stt-simple`.

## Первый запуск

1. Откройте приложение и сохраните OpenAI API key. Он записывается в системное хранилище, не в настройки и не в браузерное хранилище.
2. Выберите микрофон или оставьте системный по умолчанию.
3. Выберите модель: для новых настроек по умолчанию используется `gpt-transcribe`, рекомендованный OpenAI для файловой транскрипции. Существующая выбранная модель не меняется автоматически.
4. Проверьте короткую запись кнопкой в окне приложения.
5. После распознавания вставьте результат рабочим для целевого поля сочетанием: `Ctrl+V` или `Ctrl+Shift+V` на Linux, `Cmd+V` на macOS. На Linux и macOS можно включить автоматическую вставку в настройках приложения (зависимости описаны ниже).

В списке моделей есть `gpt-transcribe`, `gpt-4o-mini-transcribe`, его snapshot `gpt-4o-mini-transcribe-2025-12-15`, `gpt-4o-transcribe`, `gpt-4o-transcribe-diarize` и `whisper-1`. Выберите «Свой ID модели…» для другого ID или snapshot: приложение проверяет формат, а доступность и совместимость с `/v1/audio/transcriptions` определяет OpenAI. Realtime-only модели не подходят для этого endpoint. Для Diarize отправляется `chunking_strategy=auto`; приложение использует только текст результата, без отображения меток говорящих.

Актуальные рекомендации: [OpenAI — файловая транскрипция](https://developers.openai.com/api/docs/guides/speech-to-text).

Смена выбранного устройства в настройках системы учитывается при следующей записи, если используется микрофон по умолчанию. Если явно выбранное устройство пропало или изменился список устройств, обновите список и выберите его снова.

## Hotkey на Ubuntu/Wayland

GNOME 42 в Ubuntu 22.04 не предоставляет универсальный прямой перехват глобальных клавиш. Поэтому первая версия использует **системное сочетание GNOME + команду `--toggle`**. Оно работает без фокуса на приложении.

В настройках приложения укажите `Super+R` (Win+R) или другое свободное сочетание и нажмите **«Сохранить настройки»**. Приложение через GSettings создаст/обновит собственную пользовательскую привязку **STT Simple** с абсолютным путем к текущему бинарнику и аргументом `--toggle`. `sudo` не нужен.

Чужие пользовательские сочетания и системные настройки клавиш не перезаписываются. Если комбинация занята известным GNOME-сочетанием, сохранение отклоняется с сообщением о конфликте. Для переназначения чужой комбинации сначала освободите её в GNOME. Захваты клавиш расширениями и сторонними приложениями не всегда можно обнаружить.

При запуске выполняется только проверка: системные настройки не изменяются без сохранения в приложении. Статус **«настроено в GNOME»** означает, что сохраненная привязка и команда соответствуют настройкам; фактический вызов нужно проверить нажатием клавиш. Кнопка сохранения доступна и без изменения полей, чтобы восстановить удаленную привязку или обновить путь.

Для ручной настройки/удаления: **Настройки → Клавиатура → Просмотр и настройка комбинаций → Пользовательские комбинации**. В других Wayland-окружениях настройте показанную команду вручную.

Для debug-сборки (замените `/path/to/STT-simple` на абсолютный путь к вашему проекту):

```text
/path/to/STT-simple/target/debug/stt-simple --toggle
```

После release-сборки:

```text
/path/to/STT-simple/target/release/stt-simple --toggle
```

В приложении показывается команда с фактическим путем к текущему исполняемому файлу. При переносе проекта или переходе с debug на release откройте новую сборку и снова сохраните настройки. Привязка сохраняется после выхода из приложения; удалить её можно в настройках GNOME.

Повторный процесс передает команду уже работающему экземпляру через single-instance plugin и завершается. Если приложение еще не запущено, `--toggle` запускает его и начинает запись при наличии сохраненного ключа.

На macOS/X11 приложение регистрирует сочетание напрямую; для macOS задано `Control+Super+R` (Ctrl+Cmd+R). В синтаксисе сочетаний `Super` на macOS означает `Command`.

## Автоматическая вставка на Linux и macOS

Настройка **«Автоматически вставлять результат»** по умолчанию выключена. Она действует только для записи, начатой глобальным hotkey и остановленной hotkey или автоматически по лимиту 10 минут. Запуск или остановка кнопкой в окне либо через меню трея оставляет только копирование. Сначала текст копируется в буфер, затем отправляется сочетание вставки.

### Linux

- **X11:** установите `xdotool` (на Ubuntu: `sudo apt install xdotool`); исполняемый файл должен быть доступен в `PATH` приложения. В зависимости от выбранного сочетания выполняется `xdotool key --clearmodifiers ctrl+v` или `xdotool key --clearmodifiers ctrl+shift+v`.
- **Wayland:** нужен `ydotool` в `PATH`; для `Ctrl+V` выполняется `ydotool key 29:1 47:1 47:0 29:0`, для `Ctrl+Shift+V` — `ydotool key 29:1 42:1 47:1 47:0 42:0 29:0`. Для современного **ydotool 1.x** пользователь должен самостоятельно настроить работающий демон `ydotoold`, доступ демона к `/dev/uinput` и доступ своего пользователя к его сокету согласно документации установленного пакета/дистрибутива. Имена и типы служб, пути сокетов и правила доступа зависят от поставки; универсальной команды настройки службы нет.
- **Ubuntu 22.04:** пакет из `apt install ydotool` может быть старой, до-1.x версией. Одна установка пакета не гарантирует совместимость и готовность автоматической вставки. Проверьте версию пакета и документацию именно этой версии; для современной 1.x используйте подходящий источник и инструкции вашего дистрибутива. Не применяйте инструкции для 1.x к legacy-пакету вслепую.
- `YDOTOOL_SOCKET` наследуется из окружения процесса STT Simple. Если сокет нестандартный, задайте переменную до запуска приложения; изменение в другом терминале не меняет окружение уже работающего экземпляра. При запуске через GNOME hotkey окружение может отличаться от терминала.
- Приложение не запускает `sudo`, не устанавливает зависимости и не меняет службы или права доступа автоматически. Не запускайте STT Simple от root и не делайте `/dev/uinput` или сокет доступными для записи всем пользователям: доступ к ним позволяет синтезировать ввод.

Включите автоматическую вставку, выберите **«Сочетание для вставки»** и сохраните настройки: `Ctrl+V` (по умолчанию) или `Ctrl+Shift+V`. Выбор недоступен при выключенной автоматической вставке и во время записи/обработки. Выберите сочетание, которое работает вручную в конкретном целевом поле. Например, `Ctrl+Shift+V` может подходить для вставки обычного текста в чат Zed или в терминал. В целевом поле Zed пользователя ручное `Ctrl+Shift+V` работает, а текущая вставка через `Ctrl+V` — нет; это не доказывает причину и не означает, что все поля Zed требуют `Ctrl+Shift+V`.

Это **одна глобальная настройка** для всех Linux-приложений: определения приложения нет, второе сочетание после первого не отправляется (нет fallback с риском двойной вставки). Успешное выполнение команды не гарантирует, что целевое приложение приняло синтетический ввод. При ошибке или тайм-ауте команды (5 секунд) текст остаётся в буфере обмена для ручной вставки.

### macOS

Включите **«Автоматически вставлять результат»** и сохраните настройки. macOS запросит разрешение **«Универсальный доступ»** для STT Simple. Селектор сочетания на macOS скрыт: независимо от сохранённого `paste_shortcut` вставка выполняется как системное `Cmd+V` только для диктовки, начатой глобальным hotkey; кнопка приложения и меню трея продолжают только копировать результат. Если разрешение отсутствует или целевое поле запрещает синтетическую вставку, текст остается в буфере обмена.

На обеих платформах не переключайте фокус в другое поле во время распознавания: результат вставляется в активное поле на момент завершения запроса. Приложение не запоминает и не восстанавливает исходное окно; если открыть окно STT Simple или другое приложение, вставка может попасть туда.

## Трей и работа в фоне

Для значка на Ubuntu GNOME должно быть включено расширение **Ubuntu AppIndicators**. Само создание tray-объекта не гарантирует, что GNOME показывает значок. Проверьте фактическое отображение и смену цветов на своей системе.

Меню трея позволяет начать/остановить запись, отменить ее, скопировать результат, открыть окно и выйти. Во время распознавания запуск новой записи и ручное копирование отключены.

На Linux закрытие окна **сворачивает** его, а не скрывает в потенциально невидимый трей. Для завершения приложения используйте «Выйти» в интерфейсе или меню трея. На macOS закрытие скрывает окно, если tray-объект создан.

## Ошибки и приватность

- Аудио захватывается Rust-бэкендом через CPAL, хранится в памяти и преобразуется в моно WAV 16 кГц. Приложение не пишет аудио на диск.
- В OpenAI отправляются аудио, выбранная модель и ключ авторизации; использование API оплачивается в вашем аккаунте OpenAI. Системный proxy может применяться HTTP-клиентом; пользовательский API endpoint не поддерживается.
- Полировка, перевод и история транскрипций отсутствуют. Последний текст доступен в памяти приложения до выхода. Автоматическая вставка опциональна: на Linux требует `xdotool` или настроенный `ydotool`, на macOS — Accessibility.
- На диск сохраняются только настройки без ключа и агрегированная статистика. Файл расположен в системном каталоге данных приложения `io.sttsimple.desktop`.
- Ключ хранится в Secret Service на Linux и Keychain на macOS. Приложение не логирует ключ, аудио, транскрипции и сырые ошибки API.
- На Wayland копирование использует `wl-copy`. **Буфер обмена не является приватным хранилищем:** `wl-copy` может использовать временный файл в `/tmp`; владелец буфера и системные менеджеры истории могут сохранять текст после выхода приложения. Это не история самого STT Simple.
- При ошибке STT буфер не изменяется. Если STT успешен, но копирование не удалось, новый текст остается в окне с кнопкой повторного копирования. При ошибке автоматической вставки распознанный текст уже находится в буфере обмена.
- Сетевой запрос ограничен 120 секундами. Копирование через `wl-copy` ограничено 5 секундами; при зависании процесс и его группа завершаются, чтобы не переписать буфер позже.

## Проверки

```sh
npm test
npm run build
cargo fmt --all --check
cargo test -p stt-core
cargo test -p stt-simple --lib
cargo check -p stt-simple
npm run tauri -- info
```

Ядро `stt-core` тестируется без GUI и настоящего OpenAI-запроса: тесты HTTP используют локальный mock-сервер. Desktop-тесты требуют системных библиотек Tauri/ALSA. После успешного обновления Rust и загрузки зависимостей используйте созданный `Cargo.lock` для воспроизводимых сборок.

Проверка реальной интеграции описана в [docs/implementation.md](docs/implementation.md). Браузерный `npm run dev` показывает только пояснение о необходимости Tauri, а не имитирует рабочий desktop-бэкенд.

## Структура

- `src/` — React/TypeScript: окно, настройки, подписка на состояния и тесты интерфейса.
- `src-tauri/` — Tauri, CPAL, трей, hotkey, системные секреты и буфер обмена.
- `crates/stt-core/` — настройки, статистика, атомарное сохранение, WAV и OpenAI-клиент.
- [docs/requirements.md](docs/requirements.md) — согласованные требования.
