# STT Simple

Настольное приложение на Tauri 2 + Rust для диктовки и озвучивания текста через собственный OpenAI API key. Текущая рабочая платформа — macOS. Linux runtime для STT и TTS реализован, но TTS на Linux пока не проверен в реальном desktop-сеансе; старые результаты проверок Ubuntu ниже относятся к диктовке и не подтверждают работу TTS.

## Возможности

- Одно нажатие STT hotkey начинает запись, повторное останавливает и отправляет аудио в OpenAI Speech-to-Text.
- Результат копируется в буфер обмена; опциональная полировка выполняется между STT и копированием. На Linux и macOS результат можно автоматически вставлять в активное поле после диктовки через hotkey.
- Пользователь копирует текст и нажимает глобальный TTS hotkey: приложение отправляет текст в OpenAI Speech API и воспроизводит сгенерированную речь из WAV в памяти.
- Повторное действие TTS останавливает и синтез, и воспроизведение. Во время записи, распознавания или полировки TTS недоступен. Запуск STT во время TTS сначала полностью останавливает вывод и освобождает аудиоустройство, затем открывает микрофон.
- Цветной значок трея: зеленый — запись, синий — распознавание, желтый — полировка или создание речи, фиолетовый — воспроизведение, красный — готовность.
- Выбор микрофона, STT/TTS-моделей, голоса, профиля обработки и двух разных горячих клавиш.
- Длительность последней записи, суммарное время и количество записей; статистику можно сбросить.
- Отмена записи без отправки аудио. В статистику входят непустые завершенные и отмененные записи, включая записи с ошибкой API.
- Лимит одной записи — 10 минут; на лимите запись автоматически отправляется на распознавание.
- Денежная стоимость не показывается и не рассчитывается. Использование STT и TTS оплачивается аккаунтом OpenAI пользователя.

## Подготовка Ubuntu 22.04

Нужны Node.js 22.12+ либо 24+, актуальный Rust stable и системные библиотеки. Не ориентируйтесь на заявленный в manifests `rust-version = 1.77.2`: текущий lockfile включает зависимости, которым нужен более новый toolchain, в том числе Edition 2024. Первый запуск установки зависимостей и Cargo использует интернет и может занять несколько минут.

```sh
rustup update stable
sudo apt update
sudo apt install build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev libasound2-dev libdbus-1-dev patchelf wl-clipboard
```

Для секретов используется GNOME Keyring / Secret Service. В обычной Ubuntu GNOME он уже установлен; хранилище должно быть запущено и разблокировано. Не используйте `sudo` для запуска приложения, npm или Cargo.

В каталоге проекта:

```sh
npm ci
npm run tauri -- dev
```

Быстрая debug-сборка со встроенным интерфейсом, без отдельного Vite-сервера:

```sh
npm run tauri -- build --debug --no-bundle
./target/debug/stt-simple
```

Если бинарник уже собран, достаточно второй команды.

Сборка `.deb`:

```sh
npm run tauri -- build --bundles deb
```

Готовые пакеты находятся в `target/release/bundle/deb/`. Установка пакета выполняется отдельно. Собранный исполняемый файл — `target/release/stt-simple`.

## Первый запуск

1. Откройте приложение и сохраните OpenAI API key. Он записывается в системное хранилище, не в настройки и не в браузерное хранилище.
2. Выберите микрофон или оставьте системный по умолчанию.
3. Для STT выберите модель. Для новых настроек по умолчанию используется `gpt-transcribe`; существующая выбранная модель не меняется автоматически.
4. Для TTS проверьте модель `gpt-4o-mini-tts`, голос `marin` и hotkey. Backend хранит значение hotkey по умолчанию как `Control+Super+A`; интерфейс macOS показывает его как `Ctrl+Cmd+A`.
5. Проверьте короткую запись кнопкой в окне приложения.
6. После распознавания вставьте результат рабочим для целевого поля сочетанием: `Ctrl+V` или `Ctrl+Shift+V` на Linux, `Cmd+V` на macOS. На Linux и macOS можно включить автоматическую вставку в настройках приложения (зависимости описаны ниже).
7. Скопируйте короткий текст и нажмите «Озвучить буфер» или TTS hotkey. Голос сгенерирован ИИ и не является голосом человека.

В списке STT-моделей есть `gpt-transcribe`, `gpt-4o-mini-transcribe`, его snapshot `gpt-4o-mini-transcribe-2025-12-15`, `gpt-4o-transcribe`, `gpt-4o-transcribe-diarize` и `whisper-1`. Выберите «Свой ID модели…» для другого ID или snapshot: приложение проверяет формат, а доступность и совместимость с `/v1/audio/transcriptions` определяет OpenAI. Realtime-only модели не подходят для этого endpoint. Для Diarize отправляется `chunking_strategy=auto`; приложение использует только текст результата, без отображения меток говорящих.

Для TTS приложение вызывает `https://api.openai.com/v1/audio/speech` с выбранными `model`, `voice`, исходным текстом и `response_format="wav"`. По умолчанию используются `gpt-4o-mini-tts` и `marin`. Можно указать другой ID модели или голоса: frontend и backend проверяют только формат — 1–128 ASCII-символов, первая буква или цифра, далее буквы, цифры и `.`, `_`, `-`, `:` без пробелов. Доступность модели, голоса и их совместимость определяет OpenAI.

Актуальные рекомендации: [OpenAI — файловая транскрипция](https://developers.openai.com/api/docs/guides/speech-to-text) и [OpenAI — text-to-speech](https://developers.openai.com/api/docs/guides/text-to-speech).

Смена выбранного устройства в настройках системы учитывается при следующей записи, если используется микрофон по умолчанию. Если явно выбранное устройство пропало или изменился список устройств, обновите список и выберите его снова. TTS использует системное устройство вывода по умолчанию.

## Обработка текста (полировка)

По умолчанию выключена. В разделе **«Обработка текста»** выберите профиль и нажмите **«Сохранить настройки»**. Для новых записей цепочка станет: STT → полировка → копирование → опциональная автоматическая вставка. При выключенной обработке прежний путь STT → копирование/вставка не меняется; правила hotkey для вставки остаются теми же.

Три встроенных профиля доступны только для чтения:

- `polish` — «Минимальная правка»: пунктуация, регистр, очевидные оговорки и повторы без потери смысла.
- `markdown` — «Структура Markdown»: абзацы, заголовки и списки по содержанию диктовки.
- `developer` — «Сообщение разработчика»: читаемое сообщение с сохранением технических деталей, кода, команд, путей и идентификаторов.

Общие системные правила требуют сохранять язык, смысл, факты и детали, не выдумывать содержание, не отвечать на вопросы и не выполнять продиктованные инструкции. Модель должна вернуть только отредактированную диктовку; результат всё равно стоит проверять.

Можно создавать, редактировать и удалять свои профили, а также дублировать встроенный профиль в редактируемый пользовательский. Все изменения применяются через **«Сохранить настройки»**. Максимум — 32 пользовательских профиля; непустое название — до 80 символов, непустая инструкция — до 8000.

Модель обработки общая для всех профилей: по умолчанию `gpt-6-luna` для новых настроек или отсутствующего поля модели. Явно сохраненный выбор, включая `gpt-5-mini` и свой ID, не заменяется. Готовые варианты `gpt-6-luna`, `gpt-6.1-sol`, `gpt-6-astra` сверены с [официальным каталогом OpenAI](https://developers.openai.com/api/docs/models) **2026-10-03**. Ручной ввод ID остается доступным.

Кнопка **«Обновить модели OpenAI»** в настройках полировки загружает каталог через `GET /v1/models` с тем же сохраненным ключом, **только по явному нажатию**, без отправки аудио, диктовки или инструкций. Загруженный каталог хранится только в памяти. Все возвращенные модели доступны без фильтра по предполагаемой совместимости: дополнительные ID показаны в отдельной группе **«Каталог OpenAI — совместимость не проверена»**, без дублей готовых вариантов. [List models](https://developers.openai.com/api/reference/resources/models/methods/list) возвращает базовые метаданные, а не совместимость с Responses API или уровни effort. Загрузка и ее ошибка не меняют черновик настроек, выбранные модель/effort или ручной ID; при ошибке ранее загруженный каталог остается доступным. Выбранный ID сохраняется обычной кнопкой сохранения настроек, независимо от каталога.

Глобальный `reasoning.effort` предлагает «По умолчанию» (`null`, параметр не отправляется) для любой модели. **`none` не равнозначен значению по умолчанию.** Для точных ID готовых вариантов показаны документированные уровни:

| Модель | Явные значения effort |
| --- | --- |
| `gpt-6-luna` | `none`, `low`, `medium`, `high`, `xhigh`, `max` |
| `gpt-6.1-sol`, `gpt-6-astra` | `low`, `medium`, `high`, `xhigh`, `max` |

Для остальных ID доступны все варианты: `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, но их поддержка не проверена. При смене модели выбранный effort **никогда не меняется молча**: несовместимое с известными возможностями значение сохраняется с предупреждением, пока пользователь сам его не изменит. Окончательно неподдерживаемое сочетание отклоняет API.

Используется тот же сохраненный OpenAI API key и Responses API `POST /v1/responses` с `store: false`. OpenAI [рекомендует Responses для всех новых проектов](https://developers.openai.com/api/docs/guides/migrate-to-responses). Текст и инструкции передаются в OpenAI отдельным **платным текстовым запросом** после STT. `store: false` не означает локальную обработку или отсутствие всех видов хранения на стороне провайдера.

При ошибке полировки приложение возвращается к готовности: ничего не копирует и не вставляет, исходный STT-текст сохраняется в памяти. **«Повторить обработку текста»** отправляет только этот текст с захваченными настройками неудавшейся задачи (профиль и его инструкция, модель, effort), но с текущим API key. Изменение или сохранение настроек после ошибки **не меняет параметры повтора**; исправленная модель/effort применится к новой записи. Повтор не запускает STT и не меняет статистику записей. При успехе он только копирует результат — **никогда не выполняет автоматическую вставку**, даже если она включена.

Успешный старт новой записи сбрасывает старый повтор; отмена этой новой записи его не возвращает. Ошибка запуска микрофона сама по себе повтор не сбрасывает. Исходный/итоговый текст и ожидающая повтора задача хранятся только в памяти и исчезают при выходе. Повторная обработка последнего успешного результата другим профилем — желательная будущая возможность (nice to have), пока не реализована. Импорта/экспорта профилей и истории транскрипций нет.

## Глобальные hotkey

На macOS и X11 приложение регистрирует STT и TTS hotkey напрямую. Для macOS значения по умолчанию — `Control+Super+R` и `Control+Super+A`, а UI отображает их как `Ctrl+Cmd+R` и `Ctrl+Cmd+A`: `Super` в сохранённом синтаксисе означает `Command`. Сочетания STT и TTS не должны совпадать.

### Ubuntu/GNOME/Wayland

GNOME 42 в Ubuntu 22.04 не предоставляет универсальный прямой перехват глобальных клавиш. Поэтому для STT используется **системное сочетание GNOME + команда `--toggle`**. Оно работает без фокуса на приложении.

В настройках приложения укажите `Super+R` (Win+R) или другое свободное сочетание и нажмите **«Сохранить настройки»**. Приложение через GSettings создаст/обновит собственную пользовательскую привязку **STT Simple** с абсолютным путем к текущему бинарнику и аргументом `--toggle`. `sudo` не нужен.

Существующая автоматическая GNOME-регистрация относится **только к STT**. Для TTS на Wayland нужно вручную создать системное сочетание для показанной приложением команды с `--toggle-tts`, например:

```text
/path/to/STT-simple/target/debug/stt-simple --toggle-tts
```

Чужие пользовательские сочетания и системные настройки клавиш не перезаписываются. Если STT-комбинация занята известным GNOME-сочетанием, сохранение отклоняется с сообщением о конфликте. Для переназначения чужой комбинации сначала освободите её в GNOME. Захваты клавиш расширениями и сторонними приложениями не всегда можно обнаружить.

При запуске выполняется только проверка STT-привязки: системные настройки не изменяются без сохранения в приложении. Статус **«настроено в GNOME»** означает, что сохраненная привязка и команда соответствуют настройкам; фактический вызов нужно проверить нажатием клавиш. Кнопка сохранения доступна и без изменения полей, чтобы восстановить удаленную STT-привязку или обновить путь.

Для ручной настройки/удаления: **Настройки → Клавиатура → Просмотр и настройка комбинаций → Пользовательские комбинации**. В других Wayland-окружениях обе команды назначаются вручную.

Команда STT для debug-сборки:

```text
/path/to/STT-simple/target/debug/stt-simple --toggle
```

После release-сборки:

```text
/path/to/STT-simple/target/release/stt-simple --toggle
```

Для TTS замените `--toggle` на `--toggle-tts`. В приложении показываются команды с фактическим путем к текущему исполняемому файлу. При переносе проекта или переходе с debug на release обновите системные привязки. GNOME-привязка STT сохраняется после выхода из приложения; удалить её можно в настройках GNOME.

Повторный процесс передает действие уже работающему экземпляру через single-instance plugin и завершается. Если приложение еще не запущено, `--toggle` запускает его и начинает запись, а `--toggle-tts` запускает TTS, при наличии сохраненного ключа и допустимого состояния.

## Автоматическая вставка на Linux и macOS

Настройка **«Автоматически вставлять результат»** по умолчанию выключена. Она действует только для записи, начатой глобальным hotkey и остановленной hotkey или автоматически по лимиту 10 минут. Запуск или остановка кнопкой в окне либо через меню трея оставляет только копирование. Сначала текст копируется в буфер, затем отправляется сочетание вставки.

### Linux

- **X11:** установите `xdotool` (на Ubuntu: `sudo apt install xdotool`); исполняемый файл должен быть доступен в `PATH` приложения. В зависимости от выбранного сочетания выполняется `xdotool key --clearmodifiers ctrl+v` или `xdotool key --clearmodifiers ctrl+shift+v`.
- **Wayland:** нужен `ydotool` в `PATH`; для `Ctrl+V` выполняется `ydotool key 29:1 47:1 47:0 29:0`, для `Ctrl+Shift+V` — `ydotool key 29:1 42:1 47:1 47:0 42:0 29:0`. Для современного **ydotool 1.x** пользователь должен самостоятельно настроить работающий демон `ydotoold`, доступ демона к `/dev/uinput` и доступ своего пользователя к его сокету согласно документации установленного пакета/дистрибутива. Имена и типы служб, пути сокетов и правила доступа зависят от поставки; универсальной команды настройки службы нет.
- **Ubuntu 22.04:** пакет из `apt install ydotool` может быть старой, до-1.x версией. Одна установка пакета не гарантирует совместимость и готовность автоматической вставки. Проверьте версию пакета и документацию именно этой версии; для современной 1.x используйте подходящий источник и инструкции вашего дистрибутива. Не применяйте инструкции для 1.x к legacy-пакету вслепую.
- `YDOTOOL_SOCKET` наследуется из окружения процесса STT Simple. Если сокет нестандартный, задайте переменную до запуска приложения; изменение в другом терминале не меняет окружение уже работающего экземпляра. При запуске через GNOME hotkey окружение может отличаться от терминала.
- Приложение не запускает `sudo`, не устанавливает зависимости и не меняет службы или права доступа автоматически. Не запускайте STT Simple от root и не делайте `/dev/uinput` или сокет доступными для записи всем пользователям: доступ к ним позволяет синтезировать ввод.

Включите автоматическую вставку, выберите **«Сочетание для вставки»** и сохраните настройки: `Ctrl+V` (по умолчанию) или `Ctrl+Shift+V`. Выбор недоступен при выключенной автоматической вставке и во время записи/обработки. Выберите сочетание, которое работает вручную в конкретном целевом поле. Например, `Ctrl+Shift+V` может подходить для вставки обычного текста в чат Zed или в терминал. В целевом поле Zed пользователя ручное `Ctrl+Shift+V` работает, а текущая вставка через `Ctrl+V` — нет; это не доказывает причину и не означает, что все поля Zed требуют `Ctrl+Shift+V`.

Это **одна глобальная настройка** для всех Linux-приложений: определения приложения нет, второе сочетание после первого не отправляется (нет fallback с риском двойной вставки). Успешное выполнение команды не гарантирует, что целевое приложение приняло синтетический ввод. При ошибке или тайм-ауте команды (5 секунд) текст остаётся в буфере обмена для ручной вставки.

### macOS

Включите **«Автоматически вставлять результат»** и сохраните настройки. macOS запросит разрешение **«Универсальный доступ»** для STT Simple. Селектор сочетания на macOS скрыт: независимо от сохранённого `paste_shortcut` вставка выполняется как системное `Cmd+V` только для диктовки, начатой глобальным hotkey; кнопка приложения и меню трея продолжают только копировать результат. Если разрешение отсутствует или целевое поле запрещает синтетическую вставку, текст остается в буфере обмена.

На обеих платформах не переключайте фокус в другое поле во время распознавания и полировки: результат вставляется в активное поле на момент завершения всей обработки. Приложение не запоминает и не восстанавливает исходное окно; если открыть окно STT Simple или другое приложение, вставка может попасть туда.

## Трей и работа в фоне

Для значка на Ubuntu GNOME должно быть включено расширение **Ubuntu AppIndicators**. Само создание tray-объекта не гарантирует, что GNOME показывает значок. Проверьте фактическое отображение и смену цветов на своей системе.

Меню трея показывает текущий статус и позволяет начать/остановить запись, озвучить/остановить озвучивание буфера, отменить запись, скопировать последний результат, открыть окно и выйти. Во время распознавания и полировки TTS, новая запись и ручное копирование отключены. Во время TTS действие записи доступно и сначала полностью останавливает аудиовывод.

На Linux закрытие окна **сворачивает** его, а не скрывает в потенциально невидимый трей. Для завершения приложения используйте «Выйти» в интерфейсе или меню трея. На macOS закрытие скрывает окно, если tray-объект создан.

## Ошибки и приватность

- Аудио захватывается Rust-бэкендом через CPAL, хранится в памяти и преобразуется в моно WAV 16 кГц. Приложение не пишет записанное аудио на диск.
- Для STT в OpenAI отправляются аудио, выбранная модель и API key; для TTS — текст из буфера, модель, голос и API key. Использование API оплачивается аккаунтом OpenAI пользователя; приложение не рассчитывает конкретную цену. Системный proxy может применяться HTTP-клиентом; пользовательский API endpoint не поддерживается.
- Полировка опциональна и отправляет исходный текст и инструкции в OpenAI дополнительным платным запросом с `store: false`. Исходный и итоговый текст, а также параметры неудавшейся задачи для повтора доступны только в памяти до выхода. Постоянной истории транскрипций нет.
- TTS принимает максимум 4096 Unicode-символов. Пустой или состоящий только из пробелов буфер отклоняется до запроса. WAV-ответ ограничен 64 MiB, сетевой timeout — 120 секунд.
- WAV-ответ TTS и воспроизведение существуют только в RAM: временные аудиофайлы и постоянная история озвучивания не создаются.
- На диск сохраняются только настройки без ключа (включая пользовательские профили и их инструкции) и агрегированная статистика. Файл расположен в системном каталоге данных приложения `io.sttsimple.desktop`.
- Автоматическая вставка опциональна: на Linux требует `xdotool` или настроенный `ydotool`, на macOS — Accessibility.
- Ключ хранится в Secret Service на Linux и Keychain на macOS. Приложение не логирует ключ, аудио, TTS-текст, транскрипции и сырые ошибки API.
- **Буфер обмена не является приватным хранилищем:** другие приложения и системные менеджеры истории могут прочитать или сохранить текст. На Wayland `wl-copy` может использовать временный файл в `/tmp`; это не история самого STT Simple.
- При ошибке STT или полировки буфер не изменяется, автоматической вставки нет; исходный текст не используется как fallback при ошибке полировки. Если обработка успешна, но копирование не удалось, итоговый текст остается в окне с кнопкой повторного копирования. При ошибке автоматической вставки итоговый текст уже находится в буфере обмена.
- При ошибке TTS показывается безопасное сообщение без тела ответа OpenAI, ключа или текста. Недействительный ключ, недоступные модель/голос, пустой и слишком большой буфер различаются отдельными сообщениями.
- Копирование и чтение через Wayland ограничены 5 секундами; при зависании процесс и его группа завершаются.

## Проверки

```sh
npm test
npm run build
cargo fmt --all --check
cargo test -p stt-core
cargo test -p stt-simple --lib
cargo check -p stt-simple
npm run tauri -- info
```

Используйте актуальный совместимый Rust stable; строгая совместимость текущего lockfile с Rust 1.77.2 не заявляется. Ядро `stt-core` тестируется без GUI и настоящего OpenAI-запроса: HTTP-тесты используют локальный mock-сервер. Desktop-тесты требуют системных библиотек Tauri и аудио. Реальный платный OpenAI TTS-запрос в текущей macOS-сессии пока не выполнялся. Linux TTS runtime реализован, но не проверен; исторические Ubuntu-проверки в `docs/implementation.md` относятся к состоянию проекта до TTS.

Проверка реальной интеграции, включая ручной чек-лист полировки, профилей и повтора после ошибки, описана в [docs/implementation.md](docs/implementation.md). Браузерный `npm run dev` показывает только пояснение о необходимости Tauri, а не имитирует рабочий desktop-бэкенд.

## Структура

- `src/` — React/TypeScript: окно, настройки, подписка на состояния и тесты интерфейса.
- `src-tauri/` — Tauri, запись и воспроизведение аудио, трей, hotkey, системные секреты и буфер обмена.
- `crates/stt-core/` — настройки, статистика, атомарное сохранение, WAV и OpenAI-клиент для STT/TTS.
- [docs/requirements.md](docs/requirements.md) — согласованные требования.
